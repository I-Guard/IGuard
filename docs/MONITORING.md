# Monitoring

## Prometheus

`monitoring/prometheus/prometheus.yml` scrapes node-exporter, cAdvisor and blackbox probes.
`rules/recording.yml` defines `iguard:node_cpu_usage_percent`, `iguard:node_memory_usage_percent`,
`iguard:node_disk_usage_percent` and per-core/container series. `rules/alerts.yml`: `HostHighCpu`,
`HostHighMemory`, `HostDiskSpaceLow`, `TargetDown`, `EndpointDown`, `HighProbeLatency`, `ContainerDown`,
`ContainerRestarting`. Alertmanager forwards them to the backend webhook.

## Grafana dashboards

Provisioned from `monitoring/grafana/dashboards` (generated by `monitoring/grafana/generate_dashboards.py`):
infrastructure-overview, linux-server-monitoring, docker-container-monitoring, application-health,
api-latency-availability, incident-alert-overview, centralized-logs.

## Logs

Promtail ships container logs to Loki (JSON pipeline with redaction). The UI's Logs explorer queries Loki through
the backend with allowlisted labels only.

## Synthetic service checks

The backend runs HTTP/HTTPS/TCP checks itself (configurable interval, timeout, retries, latency threshold) and
stores results; availability is computed from recorded checks.

## Adding a server

Run node-exporter on the host, add a scrape target, then create the server in the UI and set its
"Prometheus instance" to the `instance` label value so metrics and incidents are linked to it.

## Behavior without data

If Prometheus, Loki or Alertmanager is unreachable the UI shows "no data" or "unreachable". Missing data is never
rendered as zero and never opens or clears incidents.
